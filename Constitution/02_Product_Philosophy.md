# Chapter 2 --- Product Philosophy

**Document ID:** AXON-PHI-001\
**Status:** Accepted\
**Version:** 1.0.0\
**Classification:** Immutable Foundation

------------------------------------------------------------------------

# 1. Purpose

This chapter defines the philosophical principles that govern every
product decision within AXON. If the Vision answers **why AXON exists**,
this chapter answers **how AXON must behave**.

The philosophy defined here SHALL apply to UX, UI, AI behaviour,
engineering trade-offs, feature prioritisation, and future product
evolution.

------------------------------------------------------------------------

# 2. Scope

This chapter governs:

-   Product behaviour
-   UX philosophy
-   Feature evaluation
-   Product priorities
-   AI interaction philosophy

This chapter does not define visual design, implementation details, or
technical architecture.

------------------------------------------------------------------------

# 3. Product Philosophy

AXON is not a collection of study tools.

AXON is a system that continuously prepares, orchestrates, and improves
the student's learning process.

The product succeeds when it removes complexity without removing student
ownership.

------------------------------------------------------------------------

# 4. Core Principles

## AXON-PHI-001 --- Prepared

The product MUST feel prepared before the student arrives.

Requirements:

-   The dashboard MUST present a clear starting point.
-   The student MUST NOT have to decide where to begin.
-   Daily work MUST already be organised.

Rationale:

Preparation reduces activation energy.

------------------------------------------------------------------------

## AXON-PHI-002 --- Focused

Every interaction MUST reduce distraction.

Requirements:

-   Only one primary action SHOULD dominate each screen.
-   Secondary information MUST support, not compete with, the primary
    objective.
-   Focus Mode MUST minimise unrelated interface elements.

------------------------------------------------------------------------

## AXON-PHI-003 --- Personal

The product MUST become more valuable over time.

Requirements:

-   Recommendations SHOULD adapt using the Academic Digital Twin.
-   Repeated use SHOULD improve planning quality.
-   Personalisation MUST be based on observable behaviour rather than
    assumptions.

------------------------------------------------------------------------

## AXON-PHI-004 --- Trustworthy

Recommendations MUST be explainable.

Requirements:

-   When AXON changes a plan or recommends a topic, it SHOULD
    communicate the primary reason.
-   Confidence scores and progress indicators MUST reflect measurable
    information.
-   The product MUST avoid presenting speculation as certainty.

------------------------------------------------------------------------

## AXON-PHI-005 --- Progressive

Every completed session MUST leave the student feeling that measurable
progress occurred.

Requirements:

-   Sessions SHOULD conclude with meaningful reflection.
-   Progress SHOULD emphasise improvement over time rather than
    arbitrary statistics.
-   Completion screens MUST reinforce momentum.

------------------------------------------------------------------------

# 5. Feature Evaluation Framework

Every proposed feature SHALL answer "Yes" to all of the following
questions.

1.  Does it reduce cognitive load?
2.  Does it improve preparation?
3.  Does it strengthen focus?
4.  Does it reinforce the Academic Digital Twin?
5.  Does it preserve student agency?
6.  Can it be explained simply?

If the answer to any question is "No", the feature SHOULD be redesigned
or rejected.

------------------------------------------------------------------------

# 6. Anti-Principles

AXON SHALL NOT:

-   maximise engagement at the expense of learning,
-   encourage meaningless streaks,
-   reward superficial activity,
-   overwhelm the interface with metrics,
-   require unnecessary configuration before studying.

------------------------------------------------------------------------

# 7. Acceptance Criteria

This chapter is complete only if:

-   Product philosophy is independent of implementation.
-   Every principle has actionable requirements.
-   Anti-principles are explicit.
-   Future features can be evaluated against this framework.
